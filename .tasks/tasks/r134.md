TT;DR: Build and publish v1.3.4 so non-technical users can update Honk300 from the native tray on Windows, macOS, and Linux. Work is active on the approved terminal-backed helper design; no release tag exists yet.

## Why
The operator directly requested an always-available tray update action and authorized implementation through global publication and installation. The current CLI updater is secure and provenance-aware, but users must open a terminal and type a command themselves.

The visible terminal is deliberate: it gives package-manager and elevation prompts a reliable home and preserves actionable failures. Terminal hosts have user-configurable close/hold behavior, so the helper will remain alive after completion, clear prior progress, and leave a plain completion screen until the user closes it.

## Plan
Extend the shared finite control-surface command set with Update and route every platform menu to a private `__control-surface-update` helper launched from the exact installed executable. The runtime must only spawn the helper; the helper performs the existing updater transaction out of process so lifecycle shutdown cannot deadlock the running IPC loop.

Refactor the updater to return a typed internal outcome without changing public CLI/JSON behavior. After mutation, resolve the receipt-owned active executable, launch it through the platform's detached app path, and wait for IPC readiness. If failure or cancelled elevation stopped the runtime, restore whichever release remains authoritative before retaining the terminal with diagnostics.

Serialize helpers with a crash-recoverable platform lock. On success, clear the terminal and show the fixed completion message. On no-op, select one of 100 curated goose-themed messages; every variant must explicitly state that nothing required updating and that the window may now be closed. Failures remain deterministic and retain their diagnostic context.

Record the platform/lifecycle boundary in ADR 0038, integrate the signed macOS command resource, update current guidance/changelogs/readiness evidence, and release only through candidate -> same-SHA main -> immutable tag -> atomic publication -> fresh-public-byte/site -> installed-machine closure.

## Impact
Intended: native tray users gain a one-click update path without typing commands; successful updates relaunch the app; failures recover the prior active app and remain visible. The public updater, receipt schemas, manifest schemas, install-channel ownership, TCC/accessibility state, autostart, configuration, and user media remain unchanged.

Risks: running the updater inside the runtime would deadlock lifecycle shutdown; stale executable paths could relaunch the wrong slot; duplicate helpers could race; terminal-profile behavior could hide output; failed elevation could leave the goose stopped; packaging could omit the Mac command resource. Each risk has an explicit architectural guard and regression gate.

## Acceptance
All three supported native control surfaces expose `Update Honk300...`; one click opens a terminal and runs the exact managed updater with no manual command entry. An updated install restarts the verified active app, an up-to-date install remains running, failure restores the authoritative app when necessary, and the terminal retains an unambiguous final state. Immutable v1.3.4 is public across the full supported artifact matrix and installed/verified on the operator's Windows machine.
