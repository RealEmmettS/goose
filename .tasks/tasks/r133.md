TT;DR: Publish an immutable v1.3.3 so the Windows app launcher can leave a breakaway-permitted
integrated-terminal job, allowing Codex's command runner to return while the goose remains alive.

## Why

v1.3.0 correctly separated the public controller, transient GUI launcher, and hidden runtime, but
its qualification waited on the short-lived origin shell process rather than the surrounding
Windows job. The Codex app places commands in a job with `JOB_OBJECT_LIMIT_BREAKAWAY_OK`; a new
process group stays in that job, so the tool cell continues tracking the otherwise detached goose.
The final v1.3.2 physical lifecycle exposed the gap after its installer/updater proof passed.

The black rectangles in clipboard screenshots were investigated independently. The exact public
presenter surface contained zero opaque-black pixels, ordinary and graceful app-launched
`CAPTUREBLT` frames were transparent, and the rectangle reproduced only through a screen-copy path
that omitted the required layered-window capture flag. Renderer bytes and DWM composition do not
need a product change.

## Plan

Have only the transient GUI launcher request `CREATE_BREAKAWAY_FROM_JOB` together with the existing
`CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP` runtime flags. If Windows returns access denied
because a managed job forbids breakaway, retry the original exact-sibling windowless launch. Keep
null handles, no shell, singleton/readiness/error cleanup, installer ownership, and every runtime
control contract unchanged. Freeze and publish one new exact commit, then install and prove it in
the same Codex job.

## Impact

Breakaway-capable integrated terminals release their command runner after readiness while the
runtime and tray stay alive. Managed jobs retain their explicit containment policy instead of
turning it into a product launch failure. The main risks are accidentally spawning twice after a
non-permission failure or weakening the no-console path; the one-error fallback and exact flag
contracts keep both bounded.

## Acceptance

One exact v1.3.3 commit passes the complete local, candidate, same-SHA main, atomic publication,
all-eight-public-byte, and production-site gates. The official Alienware install matches public
bytes and receipts. From the Codex job, the origin shell and tool call return while exactly one
transparent hidden runtime remains status-responsive, duplicate start preserves it, and graceful
plus forced stop leave no process.
