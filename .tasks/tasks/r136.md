TT;DR: Publish v1.3.6 with much calmer mud defaults: natural puddles occur every 180–300 seconds, automatic tracking lasts 10–30 seconds, and fresh/manual mud defaults to 10 seconds without overwriting saved user choices.

## Why
The operator directly requested a new patch release because the goose currently becomes muddy too often and keeps tracking mud for too long. After reviewing the current 70–160 second automatic interval, 30–90 second automatic tracking window, and independent 15-second manual/config default, the operator chose the strongest offered reduction and explicitly included the manual default.

## Scope
In scope: change only the engine timing defaults for automatic puddle cadence and duration; change the fresh/manual mud default from 15 to 10 seconds; preserve schema-v2 TOML compatibility and explicit saved values; record the changed decision in ADR 0039; bump and publish v1.3.6 through the complete immutable cross-platform release process; install and verify the official public Windows bytes; close on clean main with merged branches removed.

Out of scope: exposing automatic puddle timing in TOML or the TUI; migrating an existing explicit `mud.duration_to_track_seconds`; changing the 8–15 second off-screen puddle trip, 8.5-second footprint lifetime, one-second shrink window, rendering, sounds, manners, excursion mechanics, updater behavior, packaging shape, or public schemas.

## Plan
Set `TimingOptions` automatic puddle gaps to 180–300 seconds and automatic mud windows to 10–30 seconds. Set both `ParametersTable` and `MudConfig` defaults to 10 seconds so engine-only, omitted-field, reset, and fresh-config behavior agree. Add exact default-contract tests plus persistence/effective-option coverage for an explicit existing 15-second value. Keep ADR 0016 as historical evidence and add ADR 0039 to supersede only its numeric cadence defaults.

Synchronize Cargo metadata, canonical guidance, README, both changelogs, readiness evidence, and the tracked board. Pass focused and complete local gates, exact-SHA candidate, unchanged-main CI, immutable tag publication, all public-byte lanes, production-site identity, and an official Windows update plus isolated-config smoke. Record observed hashes, SHAs, run ids, and physical results instead of projecting them.

## Impact
Intended: muddy returns become an occasional accent rather than a frequent/long desktop state, while direct `do mud` remains available with a shorter fresh default.

Possible unintended effects: mismatched defaults between engine/config, accidental migration of saved user intent, breaking deterministic puddle delivery, or leaving documentation/release metadata on the former cadence. Tests and release evidence must explicitly rule these out. No platform, lifecycle, installer, updater, or renderer behavior should change.

## Acceptance
**Functional bar:** default automatic puddles schedule 180–300 seconds apart and produce 10–30 seconds of new muddy footprints; fresh/manual mud defaults to 10 seconds; explicit saved values such as 15 seconds remain effective; unchanged footprint fade completes normally.

**Evidence bar:** focused tests and the complete local gate pass; an isolated release config materializes and exercises the new manual default without touching the real config; exact candidate and same-SHA main CI pass before tagging; immutable publication, all eight fresh-public-byte lanes, production identity, official Windows installation/update, and public-byte runtime/config proof pass.

**Gate ownership:** the operator and repository release policy require physical/public-byte release closure. No listed release gate is optional for this task.
