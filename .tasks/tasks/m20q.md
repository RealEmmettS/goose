## Why
The engine's procedural goose is correct in its golden images, but the macOS AppKit pixel bridge currently displays a nearly transparent white/purple blob. This Mac has never hosted the complete renderer, Accessibility, CLI/TUI, lifecycle, performance, signing, and release qualification together. A DMG must not be promoted until the exact published artifact is Developer ID signed, notarized, stapled, Gatekeeper accepted, installable without `sudo`, and independently verified.

This is a direct operator order. Locked decisions are v0.3.3, per-user installation at `~/Applications/Honk300.app`, API-key notarization with the current Developer ID identity for team `M9D5379H93`, an immutable atomic release, and promotion of the DMG only after the live release passes verification. The exact implementation plan is preserved in the task conversation and in the v0.3.3 readiness document as it is written.

## Plan
1. Correct the premultiplied RGBA to AppKit bitmap contract with a failing native pixel regression test, then remove per-frame conversion/allocation and profile the fixed runtime.
2. Extend the shared macOS install transaction to copy a mounted source bundle and package a signed graphical helper that invokes it.
3. Make candidate/release packaging fail closed on Developer ID signing and notarization, and retain machine-readable evidence.
4. Qualify denied and granted Accessibility, renderer semantics, engine behaviors, CLI/TUI/IPC, terminal protection, audio, lifecycle, and rollback on the exact signed artifact.
5. Run the full repository gate, candidate gate, main CI, immutable tag release, and independent fresh-download verification.
6. Update the React site, test it against the live v0.3.3 manifest, deploy a preview, then publish and verify production.

Board-visible execution gates are proper subtasks in `.tasks/TASKS.md`. This description records rationale, risks, and resume context rather than duplicating their completion state.

## Impact
Intended: macOS users see the correct goose, receive a stable Accessibility identity, can install through a no-sudo DMG, and get an Apple-notarized primary download. The macOS runtime should stop accumulating autoreleased objects and meet the recorded CPU/RSS envelope.

Risks: pixel-format changes can swap channels or alpha; AppKit object reuse can display stale frames; lifecycle changes can overwrite foreign files; signing order can invalidate nested code; release workflow changes can partially publish; website promotion can point to an absent or untrusted artifact. Every risk is gated by test-first contracts and candidate/fresh-download verification. Terminal windows remain absolutely excluded from mischief.

## Acceptance
The renderer is semantically visible on light and dark backgrounds; macOS CPU/RSS meet the v0.3.3 readiness thresholds; all automated gates pass; denied/granted native evidence is recorded; install/update/uninstall returns this Mac to its initial uninstalled state; the exact tag is atomically published with a signed/notarized/stapled DMG; and the production site recommends that verified artifact.
