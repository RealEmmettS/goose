## Why

## Plan

Use the existing smoke scripts rather than designing a second proof path. First preference is a
self-hosted macOS runner labelled `[self-hosted, macOS, ARM64, honk300-a11y]` with
`HONK300_RUN_A11Y_SMOKE=true`; fallback is a manual macOS run on a machine where `Honk300.app`
has already been granted Accessibility permission for bundle id `dev.emmetts.honk300`.
No additional macOS Accessibility investigation is part of the current M19-first continuation.

Resolution steps:

1. Run `script/smoke_m16_macos_accessibility.sh` on the pre-granted macOS host.
2. Capture the run URL or terminal transcript, including status output with
   `accessibility: supported` and `cursor: supported`.
3. Confirm the exercised commands: `honk`, `mud`, `reload`, `nab`, `meme`, `note`, and `stop`.
4. Record any manual observations for terminal non-targeting and multi-monitor behavior, noting
   hardware limits honestly.
5. Append the evidence to `docs/readiness/m16-m18-readiness.md`, then close this task only after
   the verification checklist is complete or explicitly waived with reasons.
