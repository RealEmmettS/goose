TT;DR: Ship a separately qualified, versioned GNOME Shell companion.

## Why
Native GNOME window authority belongs to its Shell/Mutter APIs and cannot inherit KDE evidence.

## Scope
An explicitly installed and enabled versioned Shell companion supplies authenticated bounded
window observations and owned-prop placement to Rust. First establish the actual compatible
visible-overlay path; do not assume layer-shell support from another compositor. Preserve
foreign extensions, GNOME settings, terminal exclusions, configuration drafts and lifecycle
ownership. Pointer permission remains a distinct native portal operation when proven.

## Plan
First run the real extension enable/disable lifecycle, Meta.Window identity/geometry and a
visible goose overlay in a disposable GNOME desktop. The cheapest falsifiers are an unavailable
overlay protocol or incompatible Shell module/API. Inspect the first failure within two native
attempts before expanding runtime/GUI wiring. Qualify versions and native architectures separately;
publication follows #rkde and requires the full project release gates.

## Acceptance
The real desktop runs the goose and only the explicitly enabled companion's proven operations.
Disable, compositor exit, permission loss and replaced windows stop actions immediately without
touching foreign extensions or restoring pointer grants. A new immutable release and website
claims are supported by the exact tested GNOME versions.

## Evidence
Authoritative sources: https://gjs.guide/extensions/development/creating.html,
https://gjs.guide/extensions/development/debugging.html and
https://gnome.pages.gitlab.gnome.org/mutter/meta/class.Window.html.
The current guidance distinguishes the newer devkit launcher from earlier nested shells.
Exact supported versions and the product's native behavior remain unverified.
