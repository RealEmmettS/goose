TT;DR: Publish v1.2.3 so the versionless official CLI bootstrap is the recommended fresh-install path on Windows, macOS, and Linux, while updates preserve the proven owner and deliberate fresh official installers safely become the new owner.

## Why
The sibling TR-300, ND-300, and SD-300 updater tasks converged on a shared lifecycle rule: command-first installation is only honest when the official bootstrap is a managed channel, not merely documentation around an unmanaged package-manager command. Goose already has managed PowerShell and shell bootstraps, but the recommendation is package-first and the Mac shell template currently preserves an old DMG receipt even when the user deliberately launches a fresh shell install.

## Plan
- Add ADR 0034, superseding only the prior package-first recommendation while retaining DMG/MSI/EXE/DEB artifacts and every provenance-preserving update rule.
- Advertise the stable `irm ... | iex` command on Windows and `curl ... | sh` on macOS/Linux; describe native packages as explicit alternatives and raw Cargo/source installs as unmanaged development paths.
- Pass trusted updater intent into the Mac bootstrap so a DMG-owned `honk300 update` keeps the DMG channel, while a fresh public shell install commits shell ownership after verification.
- Audit and test recognized-channel takeover in both directions for PowerShell versus Windows native installers, shell versus DMG on Mac, and shell versus Debian on Linux. Fail visibly where scope or ownership makes safe convergence impossible.
- Bump to v1.2.3, update technical and human changelogs, run the complete noninteractive gate, and use disposable platform-native CI for installer mutation and GUI-app qualification.
- Publish one immutable exact-SHA patch, verify public bytes/latest aliases/manifest, then update and deploy the production website copy.

## Impact
Intended: most users get one copyable versionless command and later `honk300 update` behaves predictably. Users choosing DMG, MSI, EXE, or DEB retain those formats across updates. A later fresh official installer can intentionally change channels without leaving two active owners.

Risks: a transport helper must not accidentally rewrite provenance during an update; cross-scope Windows or Linux cleanup must not claim success without authority; old signed releases and assets must remain immutable; raw Cargo must not be misrepresented as a supported takeover mechanism.

## Acceptance
Focused provenance/takeover tests pass; the complete local and exact-candidate matrices pass; the same SHA reaches main, tag, atomic release, post-release public-byte qualification, stable/latest aliases, and the production site; only main remains locally and remotely; the board records exact evidence.
