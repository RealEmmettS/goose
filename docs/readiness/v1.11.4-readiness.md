# Goose v1.11.4 readiness

Task #g17 and [ADR 0059](../adr/0059-cross-platform-managed-reinstall.md) cover installing Goose again through the website or CLI. The public baseline was v1.11.3.

## Report and reproduction

The maintainer's test used the previously published, checksum-pinned universal application and the system tool from Xcode 27.0 build 27A266a. Asking for both Intel and Apple Silicon slices in one invocation produced the reported error. Checking the same file once per architecture succeeded. A thin binary failed the check for the other architecture. An independent upstream project documented the same tool behavior. The implementation and tests came from these observations and the project's release artifacts. [Goose issue 22](https://github.com/RealEmmettS/goose/issues/22) · [Flutter's upstream change](https://github.com/flutter/flutter/pull/188625)

## Investigation and local qualification

- Public asset digests, architecture headers and Debian payload equivalence were checked against v1.11.3.
- The old GNU move command treated the active directory link as a destination directory. A 32-bit Windows PowerShell process looked under Program Files (x86). The published Linux desktop command split a spaced executable path.
- Local Rust formatting, Clippy, workspace tests, release build, Native SDK checks and packaging fixtures passed on Windows. Native x64 and 32-bit PowerShell both selected the x64 package and native Program Files.
- The initial hosted compatibility run caught the Ubuntu runner transition to glibc 2.43. The compositor probes now build on Ubuntu 24.04 on both CPUs for compatibility with the qualified distributions.
- On source 92d426e all 31 applicable PR checks passed. Candidate 45487421913 reproduced the old lipo failure on Xcode 27.0 (27A266a) and exercised the signed graphical and shell reinstall with startup off and on. The portable Windows ARM64 producer failed because cargo-xwin could no longer find ARM64 headers in the Windows SDK catalog, and the default Apple Silicon portable runner was retired. The revised plan selects native Windows ARM64 and macOS 15 Apple Silicon hosts.
- A disposable Ubuntu 22.04.5 x64 system passed the real v1.11.3 shell upgrade, rollback, repeated candidate installation, login enablement through settings, shell-to-Debian migration, Debian refresh through the bootstrap, and package removal. Configuration bytes, notes and startup survived the reinstalls. All three native Debian packaging and transaction recovery tests passed. A separate disposable Alpine 3.21.3 x64 system passed the corresponding musl upgrade, forced rollback, repeat installs, settings save, startup readback and user-media checks.
- In a disposable Ubuntu 22.04.5 guest, the real PackageKit service omitted its caller environment variable. A local package opened through that service initially refused to hand off the shell installation. With the caller read from the active Goose transaction on the system bus, the same ordinary account installed the package, retained configuration and media, and reached the package through its existing command alias. GIO also launched the actual settings window from the spaced shell install path on a virtual X11 display. Desktop password UI was outside this backend check.
- The final local Python run completed 170 cases with five platform skips. All four native Debian packaging tests passed on Ubuntu, including rejection of unrelated, queued, simulated, download-only and ambiguous PackageKit transactions.
- The Ubuntu CLI rehearsal used the exact public v1.11.3 CLI and the verified candidate manifest and payloads, supplied by a test transport inside the disposable account. The old CLI upgraded to v1.11.4. On both shell and Debian installations, the new CLI refreshed the active version and the next update reported it was current.

The Xcode 27 test models an existing installation made before upgrading Xcode. It prepares the genuine old signed app using the pinned old shell installer with just its two failing architecture invocations split. The new shell installer and signed graphical helper run as shipped. The test exercises installation through the helper and dismisses it by terminating its process after the receipt and installed payloads prove success. Physical Finder interaction, permission prompts and assistive technology acceptance remain separate from these hosted tests.

All 47 exact-tag and latest downloads matched their hashes, sidecars and inventory. Fresh-public testing then found a second macOS defect. On the same runner account, the public command alias reported unknown ownership while the direct bundle executable recognized its shell receipt. This affected both v1.11.3 and v1.11.4. The original Xcode graphic installer fix passed. The Linux release smoke also split a spaced command path in its version check. Follow-up qualification is tracked with v1.11.5 and ADR 0060.
