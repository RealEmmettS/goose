# Honk300 v1.5.0 release readiness

Opened 2026-09-08. Task #rlpi; refinement stage two. ADR 0043 owns the Linux prop
protocol and admission contract; ADR 0041 records ordered publication.

This candidate adds Honk300-owned Linux notes and complete pictures through the existing
verified Native SDK companion. X11 can animate those owned windows. Native Wayland uses
normal compositor placement and keeps privileged foreign-window/pointer operations
unsupported. CLI, TUI and GUI expose the live backend/session and separate positioning
capability. Pi 4/5 support is experimental, limited to 64-bit Raspberry Pi OS Desktop.

The first stage, v1.4.0, is published and all eight fresh-public lanes pass. The new
v1.5.0 tag names fully qualified source `af0bec1394361902dca350d5d900d5c56f391046`.
Its publication workflow is running; availability and website claims still await its
separate public-byte checks. Existing releases and the user's installation are unchanged.

ARM64 X11 notes, labwc notes and scaled four-quadrant images from the owned-props run
were visually inspected. Pixel oracles independently require the complete image and a
visible note body; accessibility text alone does not establish visible delivery.

The native implementation limits retained props across supported backends, preserves
existing notes when full and defers new work until capacity returns. Linux child loss
latches only that prop capability; standalone controls remain usable. Normal Wayland
placement is explicitly distinguished from X11 owned-window movement.

The final first-stage review fixes are integrated, including lock-held login-start
reconciliation, settings degraded-status handling, reload preservation and dashboard
transaction regressions. Their exact final-source qualification belongs to this candidate
as well as the first release.

Physical Pi performance, display/input hardware, suspend/resume and complete desktop
acceptance remain open. [Pi guidance](../raspberry-pi.md) records the supported installation
path and the physical checks to perform when a device becomes available. No KDE, portal,
GNOME, Sway or Hyprland privilege is enabled by this stage.
