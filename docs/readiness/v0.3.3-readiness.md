## Release rule

Do not create the tag until every pre-tag release blocker through the candidate run is complete on
one exact commit. Candidate mode must prove the complete artifact graph before the default branch
is advanced. Publication, fresh-download checks, and website rollout are necessarily post-tag
closure gates; do not promote the website DMG until those checkboxes also pass. Missing signing/
notarization credentials, failed performance, or incomplete Accessibility evidence fail closed.

## macOS Accessibility onboarding

- [x] Automatic UI requires the exact non-symlinked executable at the managed app path, bundle
  id `dev.emmetts.honk300`, safe bundle version/tag/full-commit metadata, and a matching
  current-user-owned `honk300.install.v1` receipt. Bare, source-tree, mounted-DMG, mismatched, and
  malformed launches retain non-prompting degraded behavior.
- [x] Prompt state lives outside TOML under the Honk300 state tree. Owner-only `0700`
  directories and an atomic `0600` per-update marker are required before native UI; symlinks,
  foreign ownership, unsafe permissions, and marker failures fail closed without a prompt loop.
- [x] The AppKit main thread requests native Accessibility consent, prefers the direct
  Accessibility Settings URL, and falls back to the general Privacy & Security pane without
  simulating input.
- [x] The platform-neutral permission wait walks to a lower-right primary-display safe anchor,
  follows topology changes, clears permission-bound/ambient work, permits direct honk, rejects
  other actions as busy, and leaves status/reload/stop available.
- [x] The managed macOS runtime polls at most once per second. Grant refreshes cursor/window
  capabilities and the watcher before starting a fresh FirstUX in the same process; revocation
  drops permission-bound state and returns to the wait without reopening UI.
- [x] Focused automated gates pass: five engine permission-wait tests, thirteen
  eligibility/marker/transition tests, all 17 macOS platform tests, and five smoke-script
  contract tests.
- [ ] With explicit test opt-ins, reset only Honk300's prompt marker and Accessibility record,

  successful reload/honk/stop, and `BUSY` for wander, mud, nab, meme, and note.
- [ ] Relaunch that same denied candidate, verify the binary hash and marker identity are
  unchanged, and have the operator confirm that neither consent UI nor Settings reopens while the
  safe wait remains controllable.
- [ ] Grant Accessibility to that still-running candidate and record elapsed transition time,
  same-process FirstUX, supported cursor/window status, and restored ordinary-window behavior
  without a rebuild or restart.
- [ ] Revoke Accessibility while that same candidate is running and record elapsed transition
  time, denied status, abandoned permission-bound work, return to the safe-edge wait, no new
